# Silver 功能文档

本文是 IDE 的全部功能说明。Silver 是安装后双击打开的桌面程序，用来在本机文件夹里持续改代码，包括改 Silver 自己的源码。桌面 EXE 和 CLI 的分工见 [desktop.md](desktop.md)。界面结构、颜色和类型见 [design.md](design.md)。功能只落在五个对象和三块区域上：对话、简报、工作项、产物、供应商；文件侧栏、编辑器、对话。

工作区里的文件、命令输出和模型工具都从这五个对象长出来。界面上不出现智能体花名册，用户看到的是工作项。

## 1. 功能地图

| 功能 | 用户在哪里用 | 写入哪个对象 |
| --- | --- | --- |
| 打开文件夹、点开文件 | 侧栏文件树、编辑器 | 对话的工作区 |
| 新建、切换、搜索对话 | 侧栏会话、输入框 | 对话 |
| 预设与模式 | 输入框胶囊 | 对话 |
| 询问与简报 | 对话列「简报」 | 简报 |
| 派发与进度 | 对话列「进度」 | 工作项 |
| 补充、修订、旁路 | 输入框，进行中也可发 | 简报或新的 Single 对话 |
| 差异、文稿、审查发现 | 对话列「改动」 | 产物 |
| 接受差异并写入文件夹 | 产物页 | 产物的接受状态、工作区文件 |
| 学术讨论与 PCB | 预设「学术讨论」 | 简报的领域字段、文稿产物 |
| 多代理与同时审计 | 检查器「进度」里的席位 | 工作项下的开发席位和审计席位 |
| 供应商与模型 | 侧栏进入的设置，占对话列 | 供应商、对话的模型 |
| 外观 | 侧栏底部 | 外观 |
| 本机保存、导出导入 | 自动保存；侧栏菜单导出 | 本机存储 |

## 2. 工作区

一条对话可以绑定一个本地文件夹。开发项目、小补丁、只读审查、写说明需要文件夹才能改代码或读仓库。学术讨论可以不绑文件夹，只产生文稿；若用户绑定了文件夹，讨论可以引用其中的原理图说明、约束笔记和已有文档。

侧栏上方是当前文件夹和文件树。点一个文件，中间的编辑器打开它，带路径和行号。文件树服务当前会话绑定的文件夹。

在输入框输入 `@` 弹出同一份文件列表，选中后把路径附到这条消息上。也可以把侧栏里的文件拖到输入框，效果相同。附件跟着这条消息走，模型只能优先读到被点名的文件，其余文件要它自己用搜索工具找。

文件夹权限：

| 写文件策略 | 能做的 |
| --- | --- |
| code | 读文件、搜索、提出代码差异；接受后写入文件夹 |
| docs | 读文件、搜索；只能新建或覆盖 Markdown 文稿 |
| none | 只读。产物停在审查发现，不出现接受写入 |

未绑定文件夹时，代码类预设仍可对话和出差异，接受按钮不可用，并说明要先绑定文件夹。

## 3. 对话

### 3.1 建立与整理

侧栏会话里有「新对话」，按开发项目建立会话。标题先用预设名，第一句用户消息发出后改成这句话的前二十个字。其他预设从输入框胶囊切换。用户可以在侧栏重命名、置顶和删除。删除只删本机记录，不删文件夹里的文件。

侧栏顶部有搜索，只匹配对话标题。会话列表按置顶在前、其余按更新时间倒序。

没有打开文件夹时，编辑器中间是打开项目。右侧输入框仍然在，第一句会按「开发项目」新建对话。

### 3.2 消息

助手的话是正文。用户的话是浅底圆角块。回复以流式追加。生成过程中输入框仍可编辑。

每条助手消息可以带：

- 假设行：已经写入简报的句子
- 选择胶囊：一轮最多四个
- 确认行：修订或升成项目时出现，含「就这样」和一条改判

消息上的动作只有复制和重试。重试从这条用户消息重新请求，并替换它后面的助手回复。进行中的工作项若依赖这次回复，先暂停，新回复回来后再对账。

底部有停止。停止保留已经流式写出的文字，进行中的工作项改为阻塞，说明「已停止，可以重试」。

快捷键：

| 按键 | 作用 |
| --- | --- |
| Enter | 发送 |
| Shift+Enter | 换行 |
| Esc | 停止生成；若检查器以盖板打开，则关闭盖板 |
| Ctrl+N | 按上一次使用的预设新建 |
| Ctrl+K | 聚焦对话搜索 |
| Ctrl+B | 折叠或展开侧栏 |
| Ctrl+I | 在对话和改动之间切换 |
| Ctrl+1 / 2 / 3 | 对话列切到简报、进度、改动 |

宽度低于 960px 时，侧栏和对话列改为盖在编辑器上的面板，功能不变。

## 4. 预设与模式

预设决定模式、默认自主度、写文件策略、检查器先打开哪一页，以及可选的领域包。

| 预设 | 模式 | 自主度 | 写文件 | 先看 | 领域包 |
| --- | --- | --- | --- | --- | --- |
| 开发项目 | Project | 自己定 | code | 简报 | 无 |
| 小补丁 | Single | 直接做 | code | 产物 | 无 |
| 只读审查 | Single | 先问 | none | 产物 | 无 |
| 写说明 | Single | 自己定 | docs | 产物 | 无 |
| 学术讨论 | Project | 先问 | docs | 简报 | PCB 设计 |

输入框上的模式胶囊显示当前预设名。点开后可换预设。对话里已经有简报或工作项时，换成另一条 Project 预设只改提示词和领域字段，不丢已有编号。换成 Single 预设时，若已有多项工作项，先问是否把当前目标收成一条小补丁并停下其余项。

Single 对话的产物页提供「升成项目」。确认后模式改为开发项目，用现有对话补一份简报，已有差异保留为产物。

## 5. 简报与询问

Project 的第一句话进入询问。系统把已经说清的写入简报，没说清的写成假设，只问还会改变计划的空项。问题显示为胶囊，用户也可以直接打字。一轮最多四个问题。用户已经给出的项不再问。

开发项目的必填项是目标、完成标准、约束、自主度。学术讨论再加领域包里仍空着的字段。Single 在一句话已经写清范围时不建简报，检查器停在产物。范围含糊，且这一改会动到多个文件或删除代码时，只问一个问题。

简报页展示：

| 字段 | 说明 |
| --- | --- |
| 目标 | 一句话 |
| 完成 | 怎样算做完 |
| R1、R2… | 稳定编号的需求。编号只增不改，删除的编号留空不再复用 |
| 约束 | 技术栈、不能动的部分 |
| 不做 | 明确排除的事 |
| 自主度 | 先问、自己定、直接做 |
| 领域字段 | 有领域包且有值才出现 |

简报页的字段可以改。没有进行中的工作项时，修改立即生效。已有工作项时，修改视作修订：对话里出现确认行，写明将暂停哪些项。点「就这样」后写入简报并按编号对账。点「这只是补充」则不改简报，把这句话注入当前工作项。

自主度：

| 档位 | 行为 |
| --- | --- |
| 先问 | 每项工作开始前在对话里确认 |
| 自己定 | 按简报做。破坏性改动、删除文件、超出简报时停下来问 |
| 直接做 | 做完把差异放进产物。删除文件和超出工作区仍然要问 |

## 6. 派发与进度

简报确认后拆成工作项。每一项记下依赖的需求编号，并带一行当前说明。能并行的项共享一个分组，进度清单里挨在一起，组标题为「同时进行」。

进度页顶部是一条总进度，宽度为已完成数除以总数。清单状态：

| 状态 | 含义 | 表现 |
| --- | --- | --- |
| pending | 还没开始 | 次要文字 |
| in_progress | 正在做 | 强调色，下面一行说明 |
| completed | 做完 | 完成色 |
| blocked | 需要人 | 橙色，说明停在哪 |
| paused | 因修订停下 | 次要文字，标题后写「已暂停」 |

点一条工作项，检查器若已在进度页则保持，产物页滚动到这项产出的差异或文稿。阻塞项在对话里同时出现一个问题，答完后该项从阻塞回到进行。

用户可以在进度页重试暂停或阻塞的项。重试只重跑这一项，不重排整个项目。

Single 的进度固定三步：看相关代码、修改、确认没有多余改动。三步都完成时进度页可以不主动打开，检查器停在产物。

工作项做完一轮后要自己判断是否达到所依赖的需求。没达到就在同一项下开下一轮，直到达到、需要人，或连续两轮缺口相同。实现契约见 [todo-agent.md](todo-agent.md)。产物交上来不等于完成。

## 6.2 长任务

长任务是同一条工作项里的连续过程：读工作区、交差异、跑检查、再按检查结果改下一轮。交过一次产物不结束这条任务。

- 席位可以多次列出目录、读文件和搜索，直到这一轮写得出差异或说得清缺口。读取次数不设上限，也不作为任务结束条件。
- 差异交给工作区之后，CLI 在该文件夹里运行允许的检查：`npm test`、类型检查、`npm run build`。退出码和输出留在这项的文稿产物里，并写进下一轮提示词。检查失败时，席位根据输出继续改。
- 停止只发生在三种情况：判断已经盖住所依赖的需求、缺的材料只有人能提供、连续两轮缺口相同。用户点「停止」时，进行中的席位改为暂停。
- 任务跑在随桌面程序启动的 CLI 里。关掉窗口或刷新界面，进行中的席位和模型调用继续留在 CLI。再次打开时，简报、进度、差异和这些席位都在，CLI 从上次状态接着调度。已经结束的请求不重复发送。

运行契约见 [desktop.md](desktop.md)。轮次判断见 [todo-agent.md](todo-agent.md)。

## 6.1 实现顺序

对照 Cursor 的子代理、Codex 的子代理，以及 Claude Code 的 Ultracode。三家都是先有一条能改代码、能看差异、能停下来的主会话，再把独立工作分给子代理。Ultracode 再进一步：计划放在可重复执行的流程里，多个代理并行，审计代理专门反驳发现，主会话只收摘要。

Silver 按这个顺序做：

1. 基础功能先能独立完成一次开发：询问、简报、派发、进度、修订、工作区读写、差异接受、New API。主会话在代理工作时仍能输入。
2. 然后才允许多代理和子代理。一次运行里要能同时有超过 8 个开发代理在写，并且至少 1 个审计代理同时在核对，而不是等开发全部结束再审计。
3. 这两段都过关之后，才做工作项自己的下一轮迭代。

多代理契约见 [multi-agent.md](multi-agent.md)。

## 7. 进行中改想法

进行中可以直接发送，不必先停止。系统先分类：

| 意图 | 条件 | 结果 |
| --- | --- | --- |
| 补充 | 不改变简报范围 | 注入当前进行中的工作项，立即生效 |
| 修订 | 简报字段或需求编号要变 | 一行确认，写明将暂停哪些项。确认后改简报并对账 |
| 旁路 | 当前是 Project，这句话只要求一处小改 | 另开一条小补丁对话，原项目继续 |

能在本地确定的先在本地确定：消息点名了某个需求编号，或领域字段的值变了，视为修订。其余由模型返回意图，界面仍按上表呈现。确认行允许把修订改判成补充。

对账规则写在客户端：

- 需求编号被删除，或正文变了：依赖它且尚未完成的项改为暂停。
- 已完成的项和它的产物保留。
- 领域字段变化视同它所绑定的编号变化。
- 新的工作项等模型按差额补上。界面不先猜测该新增什么。

## 8. 产物

产物页按类型渲染。一页可以有多份产物，按工作项分组。

| 类型 | 内容 | 动作 |
| --- | --- | --- |
| 差异 | 一个或多个文件的增删 | 逐文件接受、拒绝；全部接受 |
| 文稿 | 说明、约束清单、取舍纪要 | 复制、导出 Markdown |
| 审查发现 | 只读审查的问题列表 | 复制；可把一条发现「收成小补丁」 |

接受差异时，若写文件策略允许且已绑定文件夹，则把接受的文件写入工作区。拒绝的文件不写。再次生成同一路径的差异时，覆盖产物页上未接受的那一版；已接受的版本保留，新版本并列，标题带时间。

写文件策略为 docs 时，接受只允许 `.md`。其他差异可以看，接受按钮不可用。策略为 none 时不出现接受。

导出把当前文稿存到工作区的 `silver/` 目录；没绑定文件夹时改为浏览器下载。

## 9. 模型使用的工具

工具不出现在界面上。用户只在工作项的说明里看到「正在读」「正在改」这类一行字。失败时说明写进该项，状态改为阻塞。

| 工具 | 作用 | 受写文件策略约束 |
| --- | --- | --- |
| 列出目录 | 看工作区结构 | 否 |
| 读文件 | 读取被点名或搜到的文件 | 否 |
| 搜索 | 按文字在工作区查找 | 否 |
| 提出编辑 | 生成差异产物，不直接落盘 | 策略为 none 时不可用 |
| 写入文稿 | 生成文稿产物 | 仅 docs 与 code |
| 运行命令 | 在工作区执行测试、类型检查或构建，输出回到同一工作项 | 仅 code，且命令在允许列表内 |

允许的命令由桌面程序附带的 CLI 在工作区里执行：`npm test`、类型检查、`npm run build`。安装、删除文件和访问工作区以外的路径不在允许列表里。命令的输出收成一份文稿产物，标题为命令本身，不另开终端面板。这份输出是下一轮修改的输入。席位读完它之后继续改，直到第 6.2 节的停止条件成立。

破坏性结果，例如删除文件、改依赖锁文件、一次差异超过二十个文件，自主度即使是「直接做」也要在对话里停一次。

## 10. 学术讨论与 PCB

学术讨论是挂在 Project 上的预设，默认先问，只写文档。方向用领域包覆盖。第一包是 PCB 设计。以后的方向再挂一包，内容仍是简报字段、种子问题和文稿标题。

PCB 包并进简报的字段：

| 字段 | 绑定 | 还空着才问 |
| --- | --- | --- |
| 层数与叠层 | R1 | 这次停在约束，还是要谈到布局取舍 |
| 关键网络 | R2 | 有没有必须守住的阻抗 |
| 外形与连接器 | R3 | 外形和连接器定死了吗 |
| 加工工艺 | R3 | 用户没提加工厂时，不主动追问厂牌 |

产物是两份文稿：约束清单、取舍纪要。外形未定时，纪要不写死连接器摆位。讨论不打开板图编辑器，不产 Gerber。制造文件若以后要看，是产物页的一种新渲染。

改层数就是改 R1。依赖 R1 的取舍暂停重谈，已经对齐且仍然符合的约束留下。

学术讨论可以引用工作区里的笔记，引用写在文稿末尾，格式为相对路径。没有文件夹时不编造文件名。

## 11. 供应商与模型

协议三种：OpenAI Chat Completions、Anthropic Messages、Gemini。New API、One API、OpenRouter 以及其他兼容网关走第一种，只是地址不同。

| 预设 | 协议 | 要填的 |
| --- | --- | --- |
| New API | OpenAI | 地址、密钥、模型 |
| OpenAI | OpenAI | 密钥、模型 |
| Anthropic | Anthropic | 密钥、模型 |
| Gemini | Gemini | 密钥、模型 |
| 自定义兼容 | 三选一 | 地址、密钥、模型 |

设置从侧栏进入，盖住检查器的位置。关闭后回到原来的页。字段是分组列表：名称、协议、地址、密钥、模型。密钥输入后不明文回显。本机保存，不写入仓库，不出现在界面日志里。

「测试连接」请求模型列表。成功则把列表放进模型下拉，失败则在这一页显示状态码和一句原因，不打开新区域。对话的模型胶囊显示「供应商 · 模型」。没有可用模型时显示「未选模型」，发送前先打开设置。

每个对话选一个模型。工作项第一版不单独换模型。请求失败时，这条助手消息停下，对话里写明失败原因，并给出重试。密钥为空时不发请求。

New API 的调用：

- `GET {baseUrl}/v1/models`
- `POST {baseUrl}/v1/chat/completions`，`stream: true`
- `Authorization: Bearer {key}`

## 12. 外观与本机数据

外观三档：跟随系统、亮色、暗色。放在侧栏底部。颜色使用 Claude 的暖色表面：暗色对话 `#30302e`、侧栏 `#262624`、正文 `#faf9f5`、强调色 `#d97757`；亮色为暖纸色，正文 `#141413`，强调色 `#c6613f`。系统开启减少动态效果时，检查器展开和进度条变化改为瞬时完成。

以下内容自动存在本机：

- 对话、消息、简报、工作项、产物
- 工作区路径
- 供应商配置与密钥
- 外观

桌面版把这些记录放在本机应用数据目录。关掉窗口再打开仍然在。侧栏提供导出与导入：一份 JSON，包含对话和简报，不含密钥。导入时按对话 id 合并，同 id 以导入份为准，密钥保持本机原值。

没有账号，没有云端同步。

## 13. 异常

| 情况 | 界面 |
| --- | --- |
| 未选模型或密钥为空 | 发送被接住，检查器打开设置页 |
| 模型列表或补全失败 | 对话里一行原因，可重试 |
| 流式中断 | 保留已收到的文字。CLI 仍把该项保持为进行中，并从已保存的进度接着请求。用户点「停止」才改为暂停 |
| 文件夹不存在或无权限 | 侧栏该工作区标出原因，接受写入不可用 |
| 命令不在允许列表 | 不执行，工作项说明里写明被拒绝 |
| 修订确认还没点，用户又发一句 | 新的一句排队。先处理确认，再分类下一句 |
| 差异要写的路径逃出工作区 | 拒绝这一文件，产物里标出 |
