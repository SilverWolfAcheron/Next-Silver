# 实现与验收记录

## 第一阶段基础门禁

以下路径在 Chromium 中走过。连接通过本地 HTTP New API 兼容测试服务验证，文件操作使用浏览器实际文件句柄及隔离文件系统。部署方的远程 New API 凭据、跨域配置和系统原生目录授权界面需在部署环境验收。

| 门禁 | 界面路径与核对结果 |
| --- | --- |
| B1 主会话 | 空窗口输入第一句，自动创建开发项目。让简报回复的 HTTP 流保持打开，确认正文先出现。按 Esc 后连接关闭，正文保留。点重试，同一条用户消息重新生成。 |
| B2 简报 | 开发项目 → 输入目标 → 核对一轮至多四个问题 → 补齐后点「确认简报」。首次确认前无派发请求。检查器 → 简报可编辑。 |
| B3 进度 | 检查器 → 进度。派发同组与后续工作项，核对「同时进行」、总进度及待开始、进行中、完成；停止和修订分别验证阻塞及暂停。 |
| B4 改想法 | 工作项仍运行时发补充，核对它进入相关项。旁路打开小补丁，原项目仍有运行请求。发送指定 R1 的修订并确认，依赖 R1 的未完成项暂停，其余项和已产出的文稿保留。 |
| B5 工作区 | 侧栏 → 打开文件夹 → 展开目录 → 点文件预览。分别用 `@` 和拖拽附加。检查模型发出的列目录、读文件和搜索请求有对应结果。产物页接受一文件并核对写入内容，拒绝另一文件并核对原字节，过期差异拒写。 |
| B6 New API | 空配置发送会打开供应商设置，且没有请求。供应商 → New API → 填写地址和密钥 → 测试连接 → 下拉取得两个模型 → 保存 → 在输入框选模型。核对 `GET /v1/models`、带 Bearer 的流式 `POST /v1/chat/completions`。 |
| B7 本机记录 | 刷新后核对对话正文、修订简报、工作项状态和差异决定。侧栏 → 对话数据 → 导出 JSON，核对没有测试密钥。 |
| B8 主会话可继续输入 | 保持第一条请求的 HTTP 流打开，在输入框填写并发送第二条，看到「等待发送」。第二条未触发新请求、首条未中断。首条完成后第二条自动发出，两条均生成产物。 |

`npm run build` 通过，包含 Windows 换行相关的差异合并类型检查。

## 第二阶段开发席位和审计

开发项目确认简报后，可以为一个工作项派发多个文件范围明确的开发席位。检查器 → 进度显示该项的开发、审计和进行中数量，展开席位可读其过程摘要。模型产出的差异先合并到父项，用户在产物页接受后才写入。侧栏 → 并发设置可配置 9–32 个开发席位，审计另有 4 个名额。

| 契约验收项 | 验收结果 |
| --- | --- |
| 1. 基础门禁 | 见上表。生产构建通过。 |
| 2. 并行开发与审计 | 单元测试验证审计有独立名额。Chromium 连本地 HTTP/2 测试供应商时，服务端同时保持 9 条开发请求和 1 条审计请求。默认设置另实测同时保持 16 条开发和 4 条审计请求。 |
| 3. 范围冲突 | 单元测试验证跨工作项的大小写及 Unicode 路径冲突。浏览器验证重叠席位保持待开始，范围释放后才发出请求。 |
| 4. 即时审计 | 开发席位提交发现后立即启动审计。当时其余开发请求仍在处理。 |
| 5. 缺少审计结果 | 单元测试覆盖缺失、部分或复述。浏览器验证复述使审计阻塞，所有开发完成后父项仍在进行，产物尚未发布。 |
| 6. 保留与反驳 | 重试审计后，最终文稿只含明确保留的发现。合并差异经过用户接受后写入测试文件。主对话只收到父项启动与完成摘要。 |
| 7. 子席位 | 单元测试拒绝第三层、父范围之外的文件和越界路径。父席位等到直接子席位交回摘要后开始。 |
| 8. 并发设置 | 默认 16，保存 8 回退为 16，保存 9 后刷新保持 9。测试服务观察到设置为 9 时同时有九条开发请求。 |
| 9. 停止与修订 | Esc 关闭在途的开发和审计请求，席位变为已暂停，排队席位未继续发请求。确认需求修订也会中止受影响工作项的所有席位。 |
| 10. 旧对话 | 导入缺少 `seats` 的数据按空席位处理，Chromium 中仍可打开工作项的进度。 |

`npm test` 运行 `src/model/seats.test.ts`，覆盖验收项 2–8，并检查审计名额和停止后的调度。运行测试需支持 TypeScript 类型擦除的 Node.js 版本（22.6 或更新）。

浏览器实际并发受供应商协议和网关限流影响。同源 HTTP/1.1 连接池可能在请求到达服务端前排队。以上并发验收使用本地 HTTP/2 流，未使用远程供应商凭据。
