# 交给 Codex 的提示词（第三阶段，现在不要执行）

当前任务是 [codex-prompt.md](codex-prompt.md)：先过基础功能，再打通超过 8 个代理并发开发，并且审计同时进行。本文只在那两阶段验收通过之后使用。

把下面整段作为任务说明。不要删减验收，不要先做一版简化实现。

---

你在 Silver 仓库里实现 Todo Agent，也就是工作项的自迭代。契约是 `docs/todo-agent.md`。产品边界在 `docs/features.md`，界面边界在 `docs/design.md`。开始前读完这三份，并读 `src/state/useConversation.ts` 里的 `output()`、`pump()`、`supplement()`，以及 `src/model/types.ts` 的 `Run`。

当前代码在产物返回后就把工作项标成 `completed` 或 `blocked`。这就是缺的自迭代。你要改的是这条状态转移，不是新做一个聊天机器人。

必须做到：

- 一轮产物写完后，先用契约第 3 节的 JSON 做判断。判断不合法，或 evidence 没有覆盖该工作项的每个需求编号，父项就不得是 `completed`。
- `continue` 时在同一父项下追加下一轮，把上一轮的缺口、产物，以及 `npm test`、类型检查或 `npm run build` 的退出码和输出放进下一轮提示词。轮次不封顶。连续两轮缺口的 `requirementId` 与 `missing` 相同就停止并 `blocked`。
- 「先问」要确认才进入下一轮。「自己定」和「直接做」自动进入下一轮。删除文件、锁文件、超过 20 个文件、工作区外路径仍然先问。
- 轮次显示在现有进度页的父项下面。总进度只数父项。不新增侧栏、对话、检查器之外的区域。
- `iterations` 要进 `localData` 的读写。旧对话没有该字段时是空数组。修订暂停父项时，未完成轮次一起暂停。
- 每一轮可以多次 `list` / `read` / `search`，不要用 4 次读取把任务截断。交完差异后由 CLI 在工作区运行 `npm test`、类型检查或 `npm run build`，再把输出送回同一席位作为下一轮的输入。安装、删除和访问工作区外路径仍然拒绝。
- 修好 `src/model/diff.ts` 的换行类型错误，让 Windows 的 `\r\n` 能参与下一轮差异合并。

不允许：

- 看到有 `artifacts` 就标完成。
- 用一个 `looksGood: boolean` 或一句「请再检查一下」代替 `gaps`、`evidence` 和 `verdict`。
- 把下一轮拆成一条新的平级工作项，或另开一条对话。
- 为了少写状态，把轮次塞进 `note` 字符串。
- 跳过契约第 7 节的任何一条。每条都要有 `src/model/iterate.test.ts` 里的断言，或一条你在说明里写明的界面操作路径。界面路径不能代替第 1 到第 4 条和第 7 条，这五条必须是单元测试。
- 改颜色、预设、供应商协议，或顺手重写无关模块。

做完后运行 `npm run build`。构建失败就继续改，直到通过。最后用契约第 7 节的十条逐条对照，写明每条落在哪个测试或哪段代码，不要用「基本完成」概括。
