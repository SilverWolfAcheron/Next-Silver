# 交给 Codex 的提示词

把下面整段作为这次的任务说明。顺序不能换。不要先做自迭代，不要把多代理做成轮流排队。

---

你在 Silver 仓库里按两个阶段工作。契约是 `docs/multi-agent.md`。产品说明是 `docs/features.md`，界面说明是 `docs/design.md`。`docs/todo-agent.md` 是第三阶段，这次不要实现。

先读 `docs/multi-agent.md` 全文，再读 `src/state/useConversation.ts` 的 `output()`、`pump()`、`stop()`，以及 `src/model/types.ts`、`src/inspector/ProgressView.tsx`、`src/model/localData.ts`。

第一阶段只修基础功能，直到 B1 到 B8 都成立，并且 `npm run build` 通过。`src/model/diff.ts` 里 Windows 换行 `\r\n` 的类型错误必须修好，否则差异无法在本机文件上合并。基础功能没过关之前，不要新增席位，不要调用子代理。

基础功能过关之后再做第二阶段。第二阶段要同时满足两件事：一次运行里可以有超过 8 个开发席位同时处于 `in_progress`，并且在这些开发席位还没全部结束时，至少有 1 个审计席位也处于 `in_progress`。默认开发并发是 16。配置小于 9 时保存为 16。审计最多 4 个同时进行，不占用那 16 个开发名额。

席位挂在现有工作项上。开发席位写自己的路径范围，只把摘要交回父项。审计席位只读，必须反驳或保留每一条发现，不能把开发席位的原话再写一遍当成通过。范围重叠的开发席位不能同时写。子代理最多两层，范围不能超出父席位。主对话只收短摘要，长过程留在进度页的席位上。不新增侧栏、对话、检查器之外的区域。

不允许：

- 用 `for` 循环把 9 个席位依次 `await` 完，再启动审计，然后声称支持并发。
- 用 9 条普通工作项代替席位，让现有 `pump()` 的分组逻辑碰巧排队。
- 审计只在全部开发席位完成之后才创建。
- 没有审计记录就把父项标成 `completed`。
- 这次去实现自迭代轮次、`looksGood`，或工作项内部的下一轮判断。
- 改颜色、预设名单、供应商协议。

验收以 `docs/multi-agent.md` 第 6 节为准。第 2 到第 8 条必须写进 `src/model/seats.test.ts`。第 1 条写清每条基础功能的界面路径。最后逐条对照，写明落点。构建失败就继续改，直到 `npm run build` 通过。不要用「基本完成」概括。
